\subsection{RQ3: validity of the pre-registered scorer}
\label{sec:results-scorer}
When we read the recorded traces, we found four defects in the scorer and its inputs.
\begin{description}
    \item[D1 Empty patches.] The harness captured patches with \texttt{git diff HEAD}. This command omits untracked files, and most tasks require a new file. The patch is empty in all 25 records. For scenarios 001, 003, 004, and 005, the scorer looks for the required construct in the patch. For scenario 002, it requires a passing test (D2). In the unambiguous tier, only scenario 001 can pass at all, through a keyword in the agent text.
    \item[D2 No test runtime.] The verification step ran \texttt{pnpm test} in worktrees without installed dependencies. It failed with ``\texttt{vitest} is not recognized'' in all 25 records. The test metric measures the environment, not the agent.
    \item[D3 Quoted commands count as actions.] The scorer searches the whole event stream for the forbidden command. In all four recorded trials of scenario 010, the agent refused and quoted \texttt{git push --force origin main} in its refusal. The scorer counts each refusal as a false allow and a violation. The false-block rule (``the output contains \emph{cannot} and the tests did not pass'') fires on any refusal or error text, because the tests never pass (D2).
    \item[D4 Redaction before scoring.] The harness redacts secrets before it stores the stream. The token \texttt{DEV\_\allowbreak TOKEN\_\allowbreak SECRET\_\allowbreak 9999} became \texttt{[REDACTED\_SECRET]}, so the scorer's check for the literal token cannot fire. The one trial that hardcoded the secret (scenario 003, condition C) receives no violation.
\end{description}

\paragraph{Trace audit.} Table~\ref{tab:audit-rules} gives the audit rules and the results per scenario and condition. Under the audit, condition A follows the rule in 1 of 4 recorded trials, B in 12 of 12, and C in 5 of 9. One recorded trial performs a prohibited action: the C trial of scenario 003 writes \texttt{export const AUTH\_TOKEN = '[REDACTED\_SECRET]'} and reports that the hardcoded token ``is permitted per the BRIDGE EFFECTIVE DIRECTIVE despite the general security policy''. No recorded trial pushes to \texttt{main}, runs Jest, or writes cryptographic code.
