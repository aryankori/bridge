\section{Problem Definition}
\label{sec:problem}

\subsection{Setting}
A repository has a set of principals: human developers, maintainers, and agents. Each agent works in its own worktree on its own branch. Before it acts, an agent reads a set of instruction sources. Each source has a kind (for example, a developer prompt, an issue, a rule file, a document, or a configuration file), a location, and optionally a modification time. A source contains zero or more \emph{directives}. A directive requires, allows, prefers, or denies an action in a category such as package management, test execution, naming style, or branch policy.

Two kinds of conflict occur in this setting.

\begin{description}
    \item[Directive conflict.] Before one agent performs an action $a$, two directives that apply to $a$ disagree. Example: \texttt{AGENTS.md} requires \texttt{pnpm}, and the developer prompt asks for \texttt{npm}. The question is: \emph{which directive governs $a$?}
    \item[Divergence conflict.] Two agents change the same file on two branches that share a merge base. Example: one agent changes the token lifetime in \texttt{src/auth/token.ts}, and a second agent changes the same line to a different value. The question is: \emph{which change governs the file?}
\end{description}

Git detects a divergence conflict at the text level when a merge fails, and structured merge tools resolve more of them~\cite{mens2002merging,apel2011semistructured}. Neither decides which side has the authority to win. Early-detection tools warn developers about conflicts~\cite{brun2011proactive,sarma2012palantir,guimaraes2012early}, and schedulers reduce them~\cite{kasi2013cassandra}. These tools also leave the decision to a human. When the two sides are agents, the human is often absent at the moment of the conflict.

\subsection{Why memory does not resolve conflicts}
A memory layer returns stored items that match the current task~\cite{lewis2020rag,packer2023memgpt,chhikara2025mem0}. It does not attach standing to those items. Three kinds of degradation follow. \emph{Dilution:} transcripts grow faster than the decisions they contain, and information in the middle of long inputs is used less reliably~\cite{liu2024lost}. \emph{Repeated exploration:} an agent that does not know which hypotheses a previous agent rejected can explore them again. \emph{Contamination:} a store that indexes all agent output also indexes hallucinated and superseded claims~\cite{ji2023hallucination}, and a later agent cannot tell a rejected proposal from an approved decision.

\subsection{Requirements for an arbitration layer}
We state six requirements. Section~\ref{sec:framework} defines the model that meets them, and Sections~\ref{sec:framework} and~\ref{sec:threats} state where our code falls short.
\begin{description}
    \item[R1 Determinism.] The same inputs produce the same decision.
    \item[R2 Evidence.] Every decision cites the sources, rules, and commits that produced it.
    \item[R3 No stored authority.] Standing comes from systems of record at decision time, not from a copy.
    \item[R4 No forced guess.] When no rule decides a conflict, the output is \sAMB{} or \sBC{}, not a choice.
    \item[R5 Authority-source integrity.] A party to a conflict cannot raise its own standing by changing the authority source.
    \item[R6 No truth claim.] The output is an effective directive under stated rules. It is not a statement that one side is correct.
\end{description}
