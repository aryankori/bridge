\section{Related Work}
\label{sec:related}

\paragraph{Multi-agent LLM systems for software engineering.}
ChatDev organizes agents as a software company that communicates through chat chains~\cite{qian2024chatdev}. MetaGPT encodes standard operating procedures as roles and structured artifacts~\cite{hong2023metagpt}, AutoGen provides programmable conversations between agents~\cite{wu2023autogen}, and self-collaboration assigns analyst, coder, and tester roles to one model~\cite{dong2024selfcollab}. Surveys cover LLM-based agents~\cite{wang2024survey,he2025llmmas} and LLMs for software engineering~\cite{hou2024llm4se,fan2023llm4se}. Cemri et al.\ classify failures of multi-agent LLM systems, including failures of alignment between agents~\cite{cemri2025fail}. These systems coordinate agents that one framework creates and that share one protocol. In our setting, independent agents from different vendors meet only in the repository, and the open question is whose instruction or change has authority, not who plays which role.

\paragraph{Coding agents and their benchmarks.}
SWE-bench measures whether a model resolves real GitHub issues~\cite{jimenez2024swebench}. SWE-agent designs an agent-computer interface for this task~\cite{yang2024sweagent}, OpenHands provides an open agent platform~\cite{wang2025openhands}, AutoCodeRover combines code search with repair~\cite{zhang2024autocoderover}, and Agentless shows that a fixed pipeline is competitive~\cite{xia2024agentless}. Many of these agents build on reasoning-and-acting loops~\cite{yao2023react} and self-reflection~\cite{shinn2023reflexion}. The benchmarks score the task success of one agent against a test. None scores whether an agent follows the governing instruction when its sources conflict, which is the property that EXP-004 and EXP-005 target.

\paragraph{Context, memory, and retrieval.}
Retrieval-augmented generation adds retrieved documents to the model input~\cite{lewis2020rag}. MemGPT manages context in tiers~\cite{packer2023memgpt}. Mem0 and Zep store extracted facts or a temporal knowledge graph across sessions~\cite{chhikara2025mem0,rasmussen2025zep}, and Honcho and Cognee offer similar layers~\cite{honcho2026,cognee2026}. Zep records when a fact became invalid, which is close to our \st{Obsolete} state, but it does not decide which source may invalidate a fact. Evidence on long contexts motivates selective context~\cite{liu2024lost,hsieh2024ruler,bai2024longbench,shi2023distracted}. Memory systems improve recall. Effective standing adds a decision rule over what is recalled.

\paragraph{Instruction precedence and injection.}
The instruction hierarchy trains models to rank system, user, and tool instructions~\cite{wallace2024hierarchy}. Indirect prompt injection shows that text in tool output can act as an instruction~\cite{greshake2023indirect}, and InjecAgent and AgentDojo measure this risk for tool-using agents~\cite{zhan2024injecagent,debenedetti2024agentdojo}. Models also defer to users against evidence~\cite{sharma2024sycophancy} and state unsupported claims~\cite{ji2023hallucination}, so an agent's report needs evidence before it carries weight. Effective standing applies the instruction hierarchy at the repository level, where sources are files, issues, and commits, and the order comes from project governance.

\paragraph{Commitments, norms, and access control.}
Section~\ref{sec:framework} builds on commitment theory~\cite{singh1999commit,singh1998acl,yolum2002flexible}, on intention as commitment~\cite{cohen1990intention}, and on commitments and conventions as the basis of coordination~\cite{jennings1993commitments}. Authorization logics define delegation through ``speaks for''~\cite{lampson1992authentication,abadi1993calculus}, trust management evaluates credentials against local policy~\cite{blaze1996trust}, RBAC grants permissions through roles~\cite{sandhu1996rbac}, and least privilege applies to agents as much as to programs~\cite{saltzer1975protection}. Moffett and Sloman, and later Lupu and Sloman, classify conflicts between management policies and resolve some of them by precedence~\cite{moffett1994policy,lupu1999conflicts}. Our resolver applies that approach to instruction sources. OAuth, SPIFFE, and Sigstore supply identities and signatures that a standing computation can consume~\cite{rfc6749,spiffe2026,newman2022sigstore}, and the NIST framework sets the accountability goals behind the evidence trail~\cite{nist2023airmf}.

\paragraph{Merge conflicts, ownership, and coordination.}
Mens surveys software merging~\cite{mens2002merging}, and semistructured merge reduces false conflicts~\cite{apel2011semistructured}. Crystal, Palant\'{i}r, and related tools detect conflicts before a merge~\cite{brun2011proactive,sarma2012palantir,guimaraes2012early}, Cassandra schedules tasks to avoid them~\cite{kasi2013cassandra}, and Ghiotto et al.\ characterize conflicts in thousands of projects~\cite{ghiotto2020merge}. Ownership predicts quality~\cite{bird2011ownership}, expertise can be mined from history~\cite{mockus2002expertise}, and coordination requirements follow from task dependencies~\cite{cataldo2006coordination}. In pull-based development, integrators decide what enters the main branch~\cite{gousios2015integrator}. CRDTs merge concurrent updates with no notion of authority~\cite{shapiro2011crdt}, and physical time does not order events across processes~\cite{lamport1978time}, so recency is a policy, not a causal fact. \texttt{bridge resolve} automates one integrator decision for agent branches, and only when the ownership records decide it.

\paragraph{Empirical method for LLM studies.}
We follow guidelines for experiments~\cite{wohlin2012experimentation}, case studies~\cite{runeson2009case}, and empirical standards~\cite{ralph2020standards}, and the threats that Sallou et al.\ list for LLM-based studies~\cite{sallou2024breaking}. EXP-005 does not yet meet them (Section~\ref{sec:threats}).
