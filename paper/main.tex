\begin{abstract}
Coding agents such as Claude Code and OpenCode now share repositories and read instructions from prompts, issues, rule files, documentation, and configuration. These sources often disagree, and memory layers do not record which source has the authority to decide. We rejected a first design in which a central ``Project Truth'' ledger owns project state, because it duplicates existing systems of record and becomes a synchronization bottleneck. The replacement, \emph{effective standing}, computes at run time which directive or branch has standing in a conflict, from records such as CODEOWNERS and commit signatures. We contribute a formal model (a five-state claim lifecycle, an authority order $\succA$, and a deterministic resolution operator $\Res$), two implementations of $\Res$ (a directive resolver and \texttt{bridge resolve}, which arbitrates divergent agent worktrees), and an evaluation that reports its negative results. On a 40-scenario benchmark, the resolver agrees with 35 of 40 gold statuses; all five disagreements are between \sP{} and \sPWO{}, and no restricted action receives a permissive status. A 60-trial live-agent pilot recorded only 25 trials, and its pre-registered scorer has four measurement defects: a post-hoc trace audit disagrees with 15 of its 25 correctness verdicts. The pilot does not show that Bridge directives help agents. It does show how they fail: in one trial, an agent cited a coarse \sP{} status to justify a hardcoded secret. We define three lifecycle failure classes and state which ones the data can and cannot show.
\end{abstract}
